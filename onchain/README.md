# DuDucks Smart Contracts

Solidity smart contracts for government document verification on Base Sepolia blockchain.

## Overview

### Contracts

1. **VerificationRegistry.sol** - Main contract for storing and managing document verifications
2. **Groth16Verifier.sol** - Verifies zero-knowledge proofs generated by Circom circuits
3. **IVerifier.sol** - Interface for proof verification

## Setup

### Prerequisites

```bash
# Install Foundry
curl -L https://foundry.paradigm.xyz | bash
foundryup

# Verify installation
forge --version
anvil --version
cast --version
```

### Installation

```bash
cd onchain

# Install dependencies
forge install

# Update .env.example to .env
cp .env.example .env

# Set environment variables
# PRIVATE_KEY_RELAYER - Private key of the relayer account
# BASE_SEPOLIA_RPC - RPC URL for Base Sepolia
# BASESCAN_API_KEY - For contract verification
```

## Contract Architecture

### VerificationRegistry

Stores and manages document verifications on-chain.

**Key Functions:**

```solidity
// Submit a verification (only relayer can call)
function submitVerification(
    address user,
    string memory documentType,
    bytes32 proofHash
) external onlyRelayer

// Get verification status
function getVerificationStatus(
    address user,
    string memory documentType
) external view returns (VerificationRecord memory)

// Revoke a verification (admin only)
function revokeVerification(
    address user,
    string memory documentType
) external onlyAdmin
```

**Data Structure:**

```solidity
struct VerificationRecord {
    address user;
    string documentType;
    bytes32 proofHash;
    VerificationStatus status;
    uint256 timestamp;
    uint256 expiryTime;
}
```

### Groth16Verifier

Verifies zero-knowledge proofs using Groth16 proving system.

**Key Functions:**

```solidity
// Verify a Groth16 proof
function verify(
    uint[2] calldata proof_a,
    uint[2][2] calldata proof_b,
    uint[2] calldata proof_c,
    uint[1] calldata input
) public returns (bool)
```

## Relayer System

The relayer is a backend service that:

1. Receives signed verification requests from users
2. Verifies the user's signature
3. Calls `submitVerification` on the registry
4. Pays gas fees (users don't pay anything)

### Relayer Allowlist

```solidity
mapping(address => bool) public allowedRelayers;

function addRelayer(address _relayer) external onlyAdmin {
    allowedRelayers[_relayer] = true;
}
```

## Gas Optimization

### Current Gas Usage

- `submitVerification`: ~80,000 gas
- `getVerificationStatus`: ~5,000 gas (view)
- `revokeVerification`: ~50,000 gas

### Optimization Strategies

1. Use `mapping` instead of arrays for O(1) lookups
2. Pack struct variables to reduce storage slots
3. Use events for off-chain indexing instead of storage
4. Consider using ERC-165 for interface detection

## Security Considerations

### Threat Model

1. **Proof Forgery** - Groth16 provides cryptographic soundness
2. **Replay Attacks** - Each submission includes unique timestamp
3. **Unauthorized Submission** - Only relayer can submit
4. **Admin Abuse** - Multi-sig implementation recommended

### Security Checklist

- [ ] Access control: `onlyRelayer`, `onlyAdmin`
- [ ] Input validation: Address != 0, valid document type
- [ ] No re-entrancy risks (no external calls to untrusted contracts)
- [ ] Proper event emission for off-chain monitoring
- [ ] Rate limiting on submissions (recommended)
